# Native Orchestrator cutover gates

**Status: required evidence, not a security or release sign-off.** Follow the [compatibility matrix](compatibility-matrix.json) and the parent task handoff. Pin the exact app and independent engine commits for each receipt. A scoped passing test is not a pass for the full gate. Preserve the existing AO route for user sessions until parity and packaged rollback have both been demonstrated.

## Shared source and verification gate

- In both repositories, trace the caller, authorization check, data owner, storage transaction and side effect for every changed entry point. Inspect the exact integrated diff, including the Rust/Electron boundary and the native worker/driver boundary. The current project workflow uses a source walkthrough, scoped diff and focused tests, **not GitNexus**. Record the trace and any unresolved edge; do not retry a denied index operation or treat missing callers as proof of safety.
- Match the worktree, branch and tree being reviewed to the intended candidate. Reconcile current `main` while preserving unrelated work; retain both the app input journal and current Guardian review injection. GitHub CI for an older head does not certify the integration. Review privacy and configuration independently of test counts: no exported conversations, settings, keys, diagnostic logs, fixture directories, or user-specific local paths in commits or assets.
- Reuse passing receipts only for unchanged code and dependencies. Pin test/runtime versions and disclose mocks. Orchestrator's Windows/Linux Node 22 CI exercises the standalone contract; Coding Tools requires its applicable Electron, renderer, provider, Rust and package/security checks on the integrated batch. Installed UI behavior, real model replies, and packaged rollback need separate receipts.

## Independent Orchestrator engine

| Boundary | Required verification before cutover |
| --- | --- |
| Handler and engines | Trace the versioned handler, router and native runtime adapter for launch, recovery, outcome and shutdown. Verify that a missing or unsupported capability fails closed; session affinity and native identities may not silently route to AO or a personal provider on failure. |
| Storage, queue and events | Review worker transactions, durable receipt reservation before dispatch, the native data-root owner lock, schema version rejection, cursor and stream budgets, WAL maintenance and cancellation. Verify after restart that only an explicit recovery request for a named safe queued turn can schedule its session queue, historical/unnamed recovery queries remain read-only, and unknown delivery blocks retries. Verify the native event page's 256 KiB encoded payload budget and the worker's default 256 MiB SQLite database-page budget under a reduced test limit. No eviction is authorized. The page budget limits growth, does not shrink existing databases, and does not include the WAL. The 4 MiB journal size limit applies on reset, not while a reader pins the WAL. Rehearse pinned-reader WAL growth, checkpoint latency, slow disk, physical disk exhaustion and power-loss recovery separately. |
| Harness and process ownership | Under explicitly approved conditions verify the real harness and scoped model/credential route. Verify creation-time or owned kernel process handle and launch-instance identity, including endpoint detachment, PID reuse and descendants on Windows. Termination must never target an unrelated process. Existing child-object and exact-turn fixture tests do not establish process-tree or live reattachment parity. |
| Plugin/transport | Verify authenticated HTTP exact loopback authority, origin rules, redirects, bounded requests, no credential output/persistence and no unintended interface binding. Keep the denied stdio launch untouched. Existing real Codex discovery without inference and installed Pi SDK with a fixture provider are scoped receipts, not live tool/model parity. |
| Migration and reversal | Require an explicitly authorized finished export or isolated pinned AO capture; never read/copy live `ao.db`. Verify exact IDs, page continuity, tool/approval outcomes, blob hashes, immutable source and failure before partial publication. Test archive reversal without replay and actual packaged upgrade/rollback in isolation. Reject unsupported branched or incomplete history; fixture import must not be reported as production history. |

## Decision and release

1. **Hold** until the approved no-cost model endpoint/ID and an authorized finished AO export or isolated capture source are available. Credentials use a permitted local binding, never chat or release files. Do not count a deterministic peer as a real reply. Do not run a harness known to create diagnostic logs under the current no-disk-logs rule.
2. Obtain exact live parity and packaged rollback receipts before AO dependency removal. Verify the new AO-free candidate again, including what happens to legacy histories and copied rehearsal state. Removal cannot be certified by a package that still contains the legacy fallback.
3. Use the existing branches and one coordinated release batch in each repository. Verify the final tested/merged source, tag, workflow commit, and actual uploaded payload digests and download URLs. The current draft and scoped CI are not merge, release or installer authorization. The installed app remains untouched without separate authorization and a safe window.
