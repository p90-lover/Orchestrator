# Native Orchestrator: release gates

**Cutover is blocked.** All checks below apply to the exact integrated candidate, not an older prerelease or a shape-compatible handler. Keep a source SHA, test command, environment, scope and result for each receipt. See [detailed cutover criteria](../cutover-gates.md) and the [compatibility matrix](../compatibility-matrix.json).

- [ ] **Static security and dependencies.** Inspect the scoped diff for secrets, authorization bypass, string-built SQL with untrusted data, unvetted dependency versions and unintended network or process capabilities. Keep queries parameterized and plugin credentials outside launch/storage payloads. Audit the package manifest, lockfile if present, and actual artifact closure. Require an approved pin for any native module. The release engine must not import or bundle the AO runtime; the offline converter may still parse exported AO data.
- [ ] **Dependency direction.** Trace the handler, router, native adapter, engine, storage worker and driver callers. The handler must not depend on a storage implementation; the worker must not import the host or driver; no cycle may bridge these layers. Match reviews to the candidate and use Git diffs and source tracing, not a stale graph index.
- [ ] **CI and regression.** Run [the Windows/Linux Node 22 workflow](../../.github/workflows/test.yml) on the pinned candidate. Exercise conflict and restart behavior, exact acceptance and steer receipts, no inference on readback, confirmed and unconfirmed cancellation, scoped approval denial, and bounded event, storage and maintenance behavior under load. A failed gate blocks promotion; capture the reason rather than replaying a write.
- [ ] **Product integration and independent model run.** Run `node scripts/check-native-coding-tools.cjs <trusted-app-checkout>` for handler/engine source integration, then separately demonstrate real inference in the actual Coding Tools chat with the approved no-cost endpoint and supported, log-compatible harness. Verify provider/account and session affinity, tool lease and approval enforcement, steering, existing history and recovery. The deterministic Codex/Pi peers are not that real-model proof.
- [ ] **Migration, build and provenance.** Use a permitted finished export and perform archive and packaged rollback rehearsal. Verify standalone and integrated candidates on supported Windows/Linux configurations, record whether artifacts are reproducible, and verify source hashes and signatures where applicable. Confirm downloadable archive and manifest bytes against the exact merged commit. See [the release and rollback sequence](../../RELEASE_PLAN.md).
