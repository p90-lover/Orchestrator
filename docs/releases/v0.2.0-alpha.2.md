# Orchestrator v0.2.0-alpha.2

**Experimental native-core reliability release. Not a production AO replacement.**

## Changes

- Preserve never-dispatched queued turns across restart; mark running turns unknown and block later dispatch until the uncertainty is explicitly resolved.
- Allow explicit recovery to schedule safe queued work without changing command identities or replaying uncertain turns.
- Batch streaming text within 100 ms or 16 KiB, bound buffered bytes and entries, reject every affected promise on storage failure, and flush before terminal state.
- Preserve pre-cancel text, await in-flight writes during disposal, and prevent empty deltas from accumulating queue entries.
- Let Codex delta notifications reach the batcher without waiting for each preceding delta's disk commit. Completion still waits for all output writes.
- Mark invalid provider acknowledgements and output-persistence failures as uncertain; retire the provider connection before another inference.
- Reject incomplete or newer database schemas without changing storage pragmas; no full database scan is added to startup.
- Add a sanitized reliability register, a machine-readable compatibility checklist, and the host crash-safe-input specification. Pending entries remain pending rather than implying certification.

## Verification and limits

The release's pull request checks run the complete standalone suite on Windows and Linux with Node 22. Targeted local tests cover the changed storage/recovery/driver/batching behavior; the task checkpoint retains exact commands and source receipts. This source release contains no installed user data, accounts, credentials or diagnostic logs.

The Coding Tools host input-journal integration is separate, unfinished work and is not shipped by this release. This prerelease does not implement all harnesses, interactive approvals, offline migration, native engine selection in production chats or AO removal. An isolated MCP self-test is not a real model conversation or a successful installed-chat cutover. Existing production chats still use AO.
